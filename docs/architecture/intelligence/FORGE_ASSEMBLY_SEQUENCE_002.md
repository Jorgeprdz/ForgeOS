
## Phase 004 — FORGE_CROSS_DOMAIN_DECISION_PROJECTION_CONTRACT

Purpose: define one neutral, read-only way to project owned domain decisions without creating another intelligence engine.

Start from Pack04/Pack07 semantics and prove reuse before adding contract shape.

Required fields conceptually include subject, source domain, decision type, truth state, priority/urgency, summary, why-now, evidence, confidence, limitations, human action, action owner/target, and as-of/valid-until.

Economic truth-state normalization belongs here.

Exit condition:

```text
NEW_BUSINESS_ENGINE=NO
DOMAIN_TRUTH_REMAINS_UPSTREAM=YES
DECISION_PROJECTION_TESTABLE=YES
ECONOMIC_STATES_UNAMBIGUOUS=YES
```

## Phase 005 — FORGE_DOMAIN_INTELLIGENCE_ACTIVATION

Purpose: activate high-value existing intelligence in the owning workspaces before rebuilding Home.

Order inside phase:
1. Pipeline: Relationship + Opportunity + Nash depth.
2. Person: identity + Timeline + relationship + quote/policy refs.
3. Cartera: Future Radar decisions/deep links.
4. Activity: governed points + Mick patterns.
5. Coach/Reports only where source/persistence boundaries are proven.

Rule: consume authority outputs; no frontend reconstruction of rules.

## Phase 006 — FORGE_PRODUCT_AND_ECONOMIC_DECISION_COMPLETION

Purpose: close product/economic decision gaps once the shared projection grammar is stable.

Scope:
- GMM product-specific decision experience using existing GMM Product Intelligence;
- richer compensation explanation/digest projection;
- advisor development/lifecycle regime explanation;
- forecast/expected/generated/earned/paid visual semantics.

No new compensation formula or product calculation.

## Phase 007 — FORGE_HOME_ATTENTION_ORCHESTRATION

Purpose: compose owned candidate decisions into a bounded Home attention queue through Alfred.

Home is built **after** domain activation.

Inputs may include:
- Pipeline candidate decisions;
- Cartera/Future Radar;
- Productivity/Activity;
- Income/Forecast context;
- Agenda/Tasks;
- Coach/BI only when governed.

Home may rank/present within an attention budget but must preserve source domain and delegate actions.

## Phase 009 — FORGE_COMMERCIAL_LOOP_INTELLIGENCE_ACCEPTANCE

Purpose: prove the assembled operating loop with one clean advisor and isolated second advisor.

Required journey:

```text
Login
→ create Prospect
→ activity / commitment
→ Pipeline intelligence
→ quote
→ product-specific decision
→ close
→ explicit identity convergence
→ policy / Cartera
→ confirmed economic event when applicable
→ commission / Income truth-state presentation
→ Home reflects updated attention
→ logout/login persistence
```

Acceptance dimensions:
- desktop/mobile;
- tenant isolation/RLS;
- session scrub/late-result rejection;
- unknown is not zero;
- no automatic human decision;
- decision explanation/evidence;
- no duplicate identity;
- no duplicate truth owner;
- no blank Pages/import graph failure.
